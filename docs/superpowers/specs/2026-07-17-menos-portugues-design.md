# Menos Português ao Longo do Tempo — Design Spec

**Source:** item #12 of the 12 high-impact improvements tracked in `[[project_roadmap_vision]]` memory — "Menos português ao longo do tempo," the last unstarted item. Directly reinforces the product's "adapta cada aula ao seu ritmo" marketing promise.

## Problem

The lesson-generation (`app/api/lesson/generate/route.ts`) and session-assessment (`app/api/session/[id]/assess/route.ts`) AI prompts currently instruct the model to write grammar/exercise explanations and post-session feedback as full Portuguese sentences, unconditionally — the same amount of Portuguese for a brand-new A1 student and a near-fluent C2 student. This doesn't reflect how a real teacher would adapt: an advanced student needs less hand-holding in their native language. `app/api/conversation/route.ts` already does this kind of CEFR-tiered adaptation for intervention timing (`interventionBlock`, grouped A1/A2, B1/B2, C1/C2) — this feature extends the same pattern to explanation and feedback language.

## Goal

Grammar/exercise explanations (`explanation_pt` fields generated by `lesson/generate`) and post-session feedback (`feedback_pt`/`highlight_pt` generated by `session/assess`) get shorter and progressively more English as the student's CEFR level rises, using the same three-tier grouping already established by `interventionBlock`: A1/A2 (full Portuguese, unchanged), B1/B2 (short, mixed Portuguese/English), C1/C2 (mostly English, Portuguese only when truly needed).

## Non-goals

- **`reply_pt`** (the optional Portuguese translation of each teacher reply during free conversation, already hidden behind a "Ver tradução" toggle in `MessageBubble.tsx`) is untouched — it was already adaptive (opt-in) before this feature, at every level.
- **`translation_pt`** for newly-taught vocabulary is untouched at every level — it's how the word's meaning is actually taught; removing it risks real comprehension loss, not just "more immersion." Explicitly decided against including it in scope.
- **No other Portuguese-language content** changes — not `npc_intro_pt`, not `choice_explanation_pt`, not mission titles/descriptions, not any static UI copy. Only the specific AI-generated fields named above.
- **No new AI call anywhere** — this reuses the two AI calls `lesson/generate` and `session/assess` already make; only the prompt text sent to each changes.
- **No new database column, no new schema.** `explanation_pt`/`feedback_pt`/`highlight_pt` remain plain `string` fields — only their generated content varies.
- **No user-visible indicator or setting.** This is an invisible content-generation adjustment, not an exposed preference.

## Shared logic: `lib/language-mix.ts` (new)

```typescript
export type PortugueseTier = 'full' | 'reduced' | 'minimal'

export function getPortugueseTier(cefrLevel: string): PortugueseTier {
  if (cefrLevel === 'A1' || cefrLevel === 'A2') return 'full'
  if (cefrLevel === 'B1' || cefrLevel === 'B2') return 'reduced'
  return 'minimal' // C1, C2
}
```

A pure function centralizing the three-tier boundary already implicitly used by `interventionBlock` in `conversation/route.ts` — this feature does not invent a new level grouping, it names and shares the existing one so `lesson/generate` and `session/assess` can't drift out of sync with each other on where the boundary falls. Each consuming route still writes its own tier-specific instruction wording (the phrasing needs differ by context — a grammar explanation vs. session feedback), only the boundary logic is shared.

## `app/api/lesson/generate/route.ts` (modified)

The prompt currently has no level-based instruction for any of its `explanation_pt` fields (`grammar_point.explanation_pt`, `grammar_exercise.explanation_pt`, each `listening_questions[].explanation_pt`, each `exercises[].explanation_pt`) — they're all implicitly "in Portuguese" per the existing JSON-schema description text. Add one instruction, computed once per request and injected as a single new line in the prompt (not per-field), so the model applies it uniformly to every `explanation_pt` it writes in that response:

```typescript
const EXPLANATION_INSTRUCTIONS: Record<PortugueseTier, string> = {
  full: 'Write every "explanation_pt" field as 1-2 full sentences in Portuguese.',
  reduced: 'Write every "explanation_pt" field as 1 short sentence, mixing in English grammar/vocabulary terms naturally.',
  minimal: 'Write every "explanation_pt" field mostly in English, with at most a couple of Portuguese words only if a term has no clear English equivalent.',
}
```

Injected as a new line, `LANGUAGE MIX: ${EXPLANATION_INSTRUCTIONS[getPortugueseTier(cefrLevel)]}`, placed in the prompt right before the `Return ONLY valid JSON:` schema block (`cefrLevel` is already computed earlier in this route's `POST()` from `context.cefrLevel`).

## `app/api/session/[id]/assess/route.ts` (modified)

Replace the two currently-fixed instruction lines:

```
feedback_pt: 2-3 motivating Portuguese sentences. Highlight progress, frame weaknesses positively. NEVER say "reprovado", "falhou", "errado".
highlight_pt: Their single biggest strength, 1 sentence in Portuguese.
```

with a tier-keyed table, preserving the same pedagogical framing (always positive, never says "reprovado"/"falhou"/"errado") at every tier — only length and language mix change:

```typescript
const FEEDBACK_INSTRUCTIONS: Record<PortugueseTier, string> = {
  full: 'feedback_pt: 2-3 motivating Portuguese sentences. Highlight progress, frame weaknesses positively. NEVER say "reprovado", "falhou", "errado".\nhighlight_pt: Their single biggest strength, 1 sentence in Portuguese.',
  reduced: 'feedback_pt: 1-2 short sentences mixing Portuguese and English naturally. Highlight progress, frame weaknesses positively. NEVER say "reprovado", "falhou", "errado".\nhighlight_pt: Their single biggest strength, 1 short sentence mixing Portuguese and English.',
  minimal: 'feedback_pt: 1 short sentence, mostly in English, with Portuguese only for a word of encouragement if natural. Frame weaknesses positively. NEVER say "reprovado", "falhou", "errado".\nhighlight_pt: Their single biggest strength, 1 short sentence mostly in English.',
}
```

The prompt interpolates `${FEEDBACK_INSTRUCTIONS[getPortugueseTier(cefrLevel)]}` at the exact point the two fixed lines currently sit (`cefrLevel` is already computed earlier in this route from the `users` table read).

## Testing

- `__tests__/lib/language-mix.test.ts` (new): `getPortugueseTier()` covering all 6 CEFR levels, confirming the grouping (A1→full, A2→full, B1→reduced, B2→reduced, C1→minimal, C2→minimal).
- `__tests__/app/api/lesson/generate.test.ts` (modified): new case asserting the prompt sent to the AI (via the mocked `mockChatCreate.mock.calls[...][0].messages[0].content`) contains the correct `EXPLANATION_INSTRUCTIONS` text for a given student's `cefr_level` — one case for an A1 student (full-tier wording present) and one for a C1 student (minimal-tier wording present).
- `__tests__/app/api/session/assess.test.ts` (modified): equivalent new case(s) asserting the correct `FEEDBACK_INSTRUCTIONS` tier text appears in the assessment prompt for a given `cefrLevel`.
- No dedicated test for the exact wording of `EXPLANATION_INSTRUCTIONS`/`FEEDBACK_INSTRUCTIONS` beyond usage in the two routes above — they're static prompt copy, same precedent as other prompt-instruction text elsewhere in this codebase (e.g. `METHODOLOGY_INSTRUCTIONS` in `lib/mastery.ts`) not being separately unit-tested for wording.
