# Personagens Recorrentes (NPCs) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give students a small, fixed cast of 5 recurring NPCs tied to specific roleplay-eligible topics. When a roleplay session lands on an NPC-mapped topic, the teacher hands the voice to that NPC, who remembers the student's last encounter (reusing the summary already generated by the existing session-memory pipeline), surfaced via an intro note before the lesson and the NPC's name during the actual roleplay exchange.

**Architecture:** A static catalog (`lib/npcs.ts`) maps 5 NPCs to 5 existing `lib/topics.ts` topic keys. A new `npc_encounters` table (one row per student+NPC pair) tracks encounter count and the last visit's summary, updated via an atomic Postgres RPC (`increment_npc_encounter`) called from the session-finalize route, reusing the summary `generateSessionMemory()` already produces — no extra AI call. `sessions.npc_key` (new column) records which NPC (if any) a session is tied to, set once at lesson-generation time when the methodology rotation lands on `'roleplay'` on an NPC-mapped topic. `/api/conversation` injects a persona-swap block into the system prompt when `npc_key` is set. On the client, `LessonEngine` resolves the NPC from the lesson's intro step and relabels the roleplay chat bubbles with the NPC's name (keeping the teacher's photo — no new avatar).

**Tech Stack:** Next.js App Router (server + client components), TypeScript, Supabase, Vitest + Testing Library.

**Design spec:** `docs/superpowers/specs/2026-07-17-personagens-recorrentes-design.md`

## Global Constraints

- Exactly 5 NPCs for v1, each mapped to exactly one topic key: `tom`→`restaurants`, `sarah`→`travel`, `mike`→`job-interview`, `anna`→`shopping`, `dr-lima`→`health`. See Task 1 for exact fields.
- NPCs only ever apply when the session's methodology is `'roleplay'` (the existing rotation in `lib/mastery.ts`) — never in `conversation`/`story`/`challenge`/`game` methodology, never in `free`/`scenario`/`guided`/`daily` session modes.
- No separate TTS voice or avatar per NPC — NPCs reuse the assigned teacher's voice and photo. Only the displayed name and the system-prompt persona change.
- `npc_encounters` is one row per (user, npc) pair, upserted — never one row per visit. `last_summary_pt` holds only the most recent encounter's summary, not a history.
- The NPC's "memory" reuses `generateSessionMemory()`'s already-generated summary — no additional AI call anywhere in this feature.
- Every new DB read/write in this feature is non-fatal: a failure is logged and the surrounding request proceeds as if no NPC were involved (matches this codebase's established resilience pattern for secondary reads/writes).
- No admin UI, no NPC gallery page, no structured fact memory beyond the single summary string — static catalog in code, same precedent as `lib/topics.ts`.

```sql
-- supabase/migrations/20260717000002_npc_recurring_characters.sql
ALTER TABLE sessions ADD COLUMN IF NOT EXISTS npc_key text;

CREATE TABLE IF NOT EXISTS npc_encounters (
  id                    uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id               uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  npc_key               text NOT NULL,
  encounter_count       integer NOT NULL DEFAULT 0,
  first_encountered_at  timestamptz,
  last_encountered_at   timestamptz,
  last_summary_pt       text,
  UNIQUE (user_id, npc_key)
);

ALTER TABLE npc_encounters ENABLE ROW LEVEL SECURITY;
CREATE POLICY "npc_encounters_self" ON npc_encounters
  FOR ALL USING (auth.uid() = user_id) WITH CHECK (auth.uid() = user_id);

CREATE OR REPLACE FUNCTION increment_npc_encounter(p_user_id uuid, p_npc_key text, p_summary_pt text)
RETURNS void AS $$
  INSERT INTO npc_encounters (user_id, npc_key, encounter_count, first_encountered_at, last_encountered_at, last_summary_pt)
  VALUES (p_user_id, p_npc_key, 1, now(), now(), p_summary_pt)
  ON CONFLICT (user_id, npc_key) DO UPDATE SET
    encounter_count = npc_encounters.encounter_count + 1,
    last_encountered_at = now(),
    last_summary_pt = p_summary_pt;
$$ LANGUAGE sql;
```

```typescript
// lib/npcs.ts
export interface Npc {
  key: string
  name: string
  emoji: string
  topicKey: string
  personalityPromptEn: string
}

export const NPCS: Npc[] = [
  { key: 'tom', name: 'Tom', emoji: '🧑‍🍳', topicKey: 'restaurants', personalityPromptEn: 'a friendly, chatty waiter at a busy restaurant, quick with recommendations' },
  { key: 'sarah', name: 'Sarah', emoji: '✈️', topicKey: 'travel', personalityPromptEn: 'a brisk but polite immigration officer at an airport, asks direct questions' },
  { key: 'mike', name: 'Mike', emoji: '💼', topicKey: 'job-interview', personalityPromptEn: 'a professional, encouraging recruiter conducting a job interview' },
  { key: 'anna', name: 'Anna', emoji: '🛍️', topicKey: 'shopping', personalityPromptEn: 'an upbeat, helpful shop assistant in a clothing store' },
  { key: 'dr-lima', name: 'Dr. Lima', emoji: '🩺', topicKey: 'health', personalityPromptEn: 'a warm, reassuring doctor at a routine checkup' },
]

export function getNpcForTopic(topicKey: string): Npc | null {
  return NPCS.find(n => n.topicKey === topicKey) ?? null
}

export function getNpcByKey(npcKey: string): Npc | null {
  return NPCS.find(n => n.key === npcKey) ?? null
}
```
